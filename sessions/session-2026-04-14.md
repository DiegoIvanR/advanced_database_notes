## What I understood

- Indexes are data structures used to speed up searches.
- B-Tree indexes are good for range queries (`>`, `<`, `BETWEEN`).
- Hash indexes are better for exact matches (`=`).
- Oracle's optimizer decides whether using an index is actually faster.
- A full table scan happens when Oracle reads the entire table because using the index would not provide enough benefit.
- Cardinality refers to how unique the values in a column are.
- High-cardinality columns are usually better candidates for indexes.
- Low-cardinality columns may not benefit much from indexing because many rows share the same value.
